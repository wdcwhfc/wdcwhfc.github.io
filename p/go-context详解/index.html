Go Context详解

Jun 24, 2026
3 minute read

‼️ By Gemini

在 Go 语言中，context 包是一个非常核心且设计精妙的工具。它主要用于在 Goroutine 之间传递上下文信息，包括：取消信号、超时时间、截止时间以及键值对（TraceID 等）。

在并发编程或微服务架构中，一个请求通常会启动多个 Goroutine（如去数据库查数据、调用下游 RPC、写日志）。如果主请求被取消或超时，我们必须有一种机制通知所有子 Goroutine 停止工作，以释放系统资源。这就是 context 的核心价值。

1. Context 接口的定义

context.Context 是一个接口，它的定义非常精简，只有 4 个方法：

type Context interface {
    // 返回该 Context 被取消或超时的截止时间
    Deadline() (deadline time.Time, ok bool)

    // 返回一个只读的 channel。当 Context 被取消或超时时，该 channel 会被 close
    // 所有的子 Goroutine 都可以通过监听这个 channel 来得知“自己该结束了”
    Done() <-chan struct{}

    // 如果 Done channel 还没关闭，返回 nil
    // 如果已经关闭，返回取消的原因（例如 Canceled 或者是 DeadlineExceeded 错误）
    Err() error

    // 根据 key 获取绑定在该 Context 上的 value（常用于传递 TraceID 等）
    Value(key any) any
}

2. Context 的派生（Derivation）

context 包采用了树状结构的设计。我们通常从一个根（Root）Context 开始，通过包装函数派生出子 Context。如果父 Context 被取消，所有的子 Context 也会被自动取消。

根 Context

  • context.Background()：最常用的根 Context，通常用在主函数、初始化、后台任务或请求的起点。
  • context.TODO()：当你还不确定该用什么 Context，或者代码还在开发中时使用的占位符。

派生函数

  1. WithCancel(parent)：返回一个子 Context 和一个 cancel 函数。调用 cancel() 会关闭该子 Context 的 Done() channel。
  2. WithDeadline(parent, d)：在 WithCancel 的基础上，增加了一个绝对截止时间 d。到了时间会自动触发取消。
  3. WithTimeout(parent, timeout)：最常用的超时控制函数，等同于 WithDeadline(parent, time.Now().Add(timeout))。
  4. WithValue(parent, key, val)：派生一个携带键值对的 Context。

场景一：超时控制 (WithTimeout)

在调用外部 API、数据库查询或耗时操作时，防止系统因为下游响应慢而卡死。

package main

import (
	"context"
	"fmt"
	"time"
)

// 模拟一个耗时的网络请求
func fetchAPI(ctx context.Context) {
	select {
	case <-time.After(3 * time.Second): // 模拟请求需要 3 秒
		fmt.Println("API 请求成功完成")
	case <-ctx.Done(): // 如果超时或被取消，这里会收到信号
		fmt.Println("API 请求取消:", ctx.Err())
	}
}

func main() {
	// 设置 1.5 秒的超时时间
	ctx, cancel := context.WithTimeout(context.Background(), 1500*time.Millisecond)
	defer cancel() // 释放资源，哪怕提前结束了也会调用

	go fetchAPI(ctx)

	// 等待足够长的时间观察结果
	time.Sleep(4 * time.Second)
}

package main

import (
	"context"
	"fmt"
	"time"
)

func worker(ctx context.Context, id int) {
	for {
		select {
		case <-ctx.Done():
			fmt.Printf("Worker %d 停止工作，原因: %v\n", id, ctx.Err())
			return
		default:
			fmt.Printf("Worker %d 正在搬砖...\n", id)
			time.Sleep(500 * time.Millisecond)
		}
	}
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())

	// 启动多个 Goroutine
	for i := 1; i <= 3; i++ {
		go worker(ctx, i)
	}

	// 运行 2 秒后，老板说不干了
	time.Sleep(2 * time.Second)
	fmt.Println("----- 主线程发起取消信号 -----")
	cancel() // 级联取消所有子 goroutine

	time.Sleep(500 * time.Millisecond) // 等待打印完毕
}

场景三：传递元数据 (WithValue)

常用于微服务中传递 TraceID（链路追踪 ID）、用户身份 Token 等全局性的非业务参数。

⚠️ 注意：不要用它来传递业务参数（比如函数要用的常规参数），它应该只包含与请求生命周期相关的元数据。

package main

import (
	"context"
	"fmt"
)

// 为了防止 key 冲突，官方推荐使用自定义未导出类型作为 key
type ctxKey string

const traceIDKey ctxKey = "trace_id"

func main() {
	// 在入口处注入 TraceID
	ctx := context.WithValue(context.Background(), traceIDKey, "REQ-10086-XYZ")

	processRequest(ctx)
}

func processRequest(ctx context.Context) {
	// 在下游的任何深度的函数中，都可以取出来
	if traceID, ok := ctx.Value(traceIDKey).(string); ok {
		fmt.Printf("[日志] 正在处理请求，TraceID: %s\n", traceID)
	} else {
		fmt.Println("[日志] 未找到 TraceID")
	}
}

4. Context 使用的最佳实践（金律）

为了写出优雅且无 Bug 的 Go 代码，请务必遵守以下规则：

  1. 作为第一个参数显式传递：习惯上，ctx context.Context 应该作为函数的第一个参数，不要把它放到结构体中（除非有特殊设计）。
  2. **不要传递 nil**：如果不确定用什么，请传递 context.TODO()，绝对不要传 nil。
  3. **记得调用 cancel()**：无论是 WithCancel、WithTimeout 还是 WithDeadline，派生出来的 cancel 函数必须被调用（通常用 defer cancel()），否则会导致 Context 树上的资源泄露。
  4. Context 是线程安全的：你可以在多个 Goroutine 中同时传递和使用同一个 ctx，不需要加锁。
