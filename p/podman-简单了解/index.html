Podman 简单了解

Apr 23, 2026
1 minute read

0x00 概述

Podman 是一个开源的容器管理工具，支持 Linux、Windows 和 macOS三个平台。Podman 首先提供一个 CLI 工具，其兼容所有的 Docker 命令， 如果习惯 docker 命令，直接把 docker 设置为 podman 的别名基本可以无障碍使用, Docker Compose 与 Dockerfile 也全都兼容。

与其他容器管理工具相同，Podman 依赖一个实现 OCI 标准的容器运行时（默认是 crun，可更换）来创建、运行容器并与宿主操作系统交互。区别于 Docker 的 containerd，Podman 使用 libpod 库来管理镜像、容器和网络。

且区别于 Docker 通过 dockerd 守护进程来进行管理，Podman 直接调用 libpod，拥有较低的内存开销，尤其无命令时几乎零开销。

0x01 For Windows

在 Windows 系统上，Podman 使用基于 WSL2 的虚拟机作为运行容器的载体。这个虚拟机默认命名为 podman-machine-default，是一个精简的 Fedora Linux 发行版环境。

完整的 podman 引擎就安装在这个虚拟机内，Windows 系统上的 Podman cli 实际通过 REST API 来与虚拟机中的 podman 引擎进行通信来完整对镜像、容器的管理，对应的镜像和容器数据也保存在虚拟机中。

譬如，PowerShell 中执行: podman run -d nginx

实际发生的事情：

+------------------+     REST API (socket)     +--------------------------+
|  Windows         |  ======================>  |  podman-machine-default  |
|                  |   "拉取nginx镜像并运行"     |  (WSL2 Fedora Linux)     |
|  podman.exe      |                           |                          |
|  (纯客户端)       |                           | Podman Engine (实际干活的) |
|  不存储任何东西    |  <======================  |   镜像: /var/lib/...      |
|                  |  "镜像拉好了，容器启动了"     |   容器进程: 运行中         |
+------------------+                           +--------------------------+

所以在 Windows 上执行 podman 命令，实际和在 podman-machine-default 虚拟机中执行 podman 命令是完全等价的。

⚠️：但是 Windows 系统上，podman 连接的是 rootful socket，默认启动的 podman-machine-default 虚拟机则是普通用户，连接的是 rootless socket。两者互相隔离，维护的是不同的容器储存目录，前者是 /var/lib/containers，后者是 ~/.local/share/containers。 在 podman-machine-default 切换到 root 用户再执行 podman 命令，才与在 Windows 系统上执行 podman 命令完全等价。
